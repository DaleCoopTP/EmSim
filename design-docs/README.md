# Проектная документация EmSim

Материалы для углублённого чтения: исходный технический дизайн, архитектурные решения, исполняемые контракты и диаграммы. Обзор системы в её текущем виде — в корневом [README.md](../README.md) и [docs/](../docs/).

| Материал | Что в нём | Где |
|---|---|---|
| RFC-001 | исходный технический дизайн: задача, цели, сценарии использования, архитектура, модель данных, критические потоки, отказоустойчивость, безопасность, ёмкость, рассмотренные альтернативы | [rfc-001-emsim.md](rfc-001-emsim.md) |
| ADR | 37 архитектурных решений, по одному на файл: контекст, варианты, решение, последствия | [adr/](adr/README.md) |
| Контракты | OpenAPI, DDL базы, JSON-схемы сценария, снимка прохождения, входа оценки, событий SSE, задач; рубрики | [contracts/](contracts/) |
| Диаграммы | компоненты и границы, последовательности критических сценариев, ER-диаграмма | [diagrams/](diagrams/) |

## Как читать

1. **RFC** написан до реализации (18.09.2026) и описывает замысел первого этапа — упражнение ДДС. Часть описанного в нём ещё не реализована (генерация сценариев моделью, озвучка Piper, рекомендация уровня), а оператор 112 появился позже. Где RFC и ADR расходятся, действует более новый ADR.
2. **ADR** — источник истины по каждому решению. Изменение решения оформляется новым ADR, который уточняет или заменяет прежний; индекс со статусами — [adr/README.md](adr/README.md).
3. **Контракты** — исполняемая спецификация: веб-клиент генерирует типы из `openapi.yaml`, импорт сценариев проверяет файлы по JSON-схемам, рубрики загружаются из `rubric.*.json`. Изменение внешнего поведения меняет контракт в том же изменении кода.

## Проверка контрактов

```bash
python3 design-docs/contracts/check.py
```

Нужны Python-пакеты `PyYAML` и `jsonschema`. Проверяются JSON-схемы, примеры, локальные ссылки OpenAPI и отрицательные примеры.

При заданном `DATABASE_URL` дополнительно применяются `schema.sql` и `check-invariants.sql`: единственная автооценка, приоритет экспертной ревизии, неизменяемость артефактов, ограничения состояний. Используйте только отдельную пустую тестовую базу: проверка создаёт схему и откатывает тестовые данные. Нужен `psql`.
