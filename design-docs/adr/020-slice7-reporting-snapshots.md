# ADR-020. Срез 7: отчётные проекции и неизменяемые PDF-снимки

Статус: accepted · 2026-09-21 · уточняет ADR-006/014

## Контекст

Финальная оценка карточки может меняться экспертной ревизией. Преподавателю нужны текущие экран и CSV, но ранее сохранённый PDF должен оставаться доказуемым документом с теми основаниями, по которым был построен. Отчёт не должен задерживать интерактивные и short-задачи.

## Решение

Отчётный модуль читает `lesson_report_rows` и формирует typed `LessonReport`. Только `finished` занятие имеет отчётную проекцию. `ready` оценки участвуют в среднем балле и распределении; `needs_review`, `unavailable`, отсутствие оценки и interrupted-карточки остаются отдельными состояниями, не нулевыми баллами.

CSV строится синхронно из текущей проекции. PDF-запрос атомарно сохраняет полное canonical JSON-основание вместе с конкретными assessment id/revision в `report_files` и ставит `report.build`. Worker рендерит исключительно сохранённый snapshot; готовый blob и task terminal-state фиксируются fenced-транзакцией. Новый запрос создаёт новую строку и новый task, поэтому уже готовый артефакт не подменяется.

PDF использует отдельный pool `report` с ограничением 1. Для кириллицы рендерер встраивает UTF-8 TrueType Go Regular. Обучаемому отдаётся отдельная безопасная проекция без эталона, evidence и экспертных внутренних комментариев.

## Последствия

`report_files.basis` содержит не только ссылки на ревизии, но и отображаемые данные; изменение ФИО или новая ревизия после постановки задачи не меняют уже заказанный PDF. Файловое content-addressed storage может сохранить orphan file при потере lease до транзакционного commit; запись БД и доступный артефакт при этом не появляются, а повтор безопасен.
