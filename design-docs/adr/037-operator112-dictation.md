# ADR-037. Оператор 112: голосовой ввод (диктовка) через локальное распознавание речи

Статус: accepted · 2026-09-29 · уточняет ADR-003 и ADR-025 для одного endpoint диктовки

## Контекст

Оператор 112 в чате с ИИ-заявителем (112-5a/5b) может только печатать. Нужна диктовка: нажал кнопку, сказал фразу, распознанный текст попал в поле ввода, оператор поправил и отправил обычной командой `send_caller_message`. Система работает офлайн, распознавание — на сервере УМЦ.

ADR-003 запрещает вызывать модели на интерактивном пути; ADR-025 сделал узкое исключение для `caller.reply` (worker). Диктовка — другой случай: оператор ждёт текст, держа кнопку, и очередь задач с опросом только добавила бы задержку и таблицу. Доменного эффекта у диктовки нет: она лишь способ набрать текст.

## Решение

- **Узкое исключение из ADR-003.** Модель распознавания речи может вызывать процесс `api`, и только из `POST /api/v1/items/{itemId}/dictation`. Вызов идёт вне любой транзакции БД, не берёт блокировок и не меняет состояние карточки, журнал и evidence. Остальные STT/TTS-вызовы (`stt.transcribe` после закрытия, `voice.render`) — по ADR-003 без изменений. ДДС исключение не затрагивает.
- **Движок за портом.** Порт `Transcriber` объявлен у потребителя (`internal/training`). Первая реализация — HTTP-клиент `whisper-server` (whisper.cpp) из `internal/platform/stt/whisper`; есть детерминированная `stub` для e2e. Следующие движки (Vosk и др.) — новые реализации порта; api, контракт и UI не меняются. Выбор — `DICTATION=off|whisper|stub`.
- **Формат — WAV PCM16, 16 кГц, моно.** Браузер сам понижает частоту, поэтому на сервере нет ffmpeg и любой движок получает одинаковый файл. Не более `DICTATION_MAX_SECONDS` (30 с) и 1,2 МБ; сервер проверяет заголовок.
- **Режим «фраза целиком».** Кнопка нажата — запись, повторное нажатие или лимит — распознавание. Потоковой выдачи нет: whisper-server её не умеет, а общий режим позволяет сравнивать движки на одних и тех же фразах.
- **Проверки до распознавания** (чтение без блокировок): элемент принадлежит пользователю либо это preview его автора; `mode=full_case`, `caller_mode=free_text`; `call_status=connected`; карточка не закрыта. Endpoint не универсальный сервис распознавания.
- **Что не храним.** Ни аудио, ни распознанный текст не пишутся в БД, blob-хранилище, audit и логи; в логах только длительность, задержка и код результата. Единственный след — необязательная метка `input: voice` у реплики оператора в `send_caller_message` (клиентское заявление, не доказательство; сервер проверяет лишь значение из `text|voice`).
- **Лимиты.** Семафор `DICTATION_CONCURRENCY` (2); ожидание слота не дольше `DICTATION_QUEUE_WAIT` (5 с), иначе `429 dictation_busy`; вызов ограничен `STT_TIMEOUT` (15 с), иначе `503 dictation_unavailable`. Повторов на сервере нет — оператор нажимает кнопку снова. Текст остаётся в поле, чат работает без диктовки.
- **UI-флаг.** Элемент `free_text` содержит `dictation {available, max_seconds}`; при `DICTATION=off` кнопки микрофона нет.
- **Компоновка.** `stt` — отдельный контейнер `whisper.cpp` в сети `inference` (без выхода наружу); GGML-модель read-only из `./models`.

## Последствия

- CPU делят `llama-server` и `whisper-server`. При 1–2 одновременных диктовках нагрузка приемлема; замер задержек вместе с `llm` — в W0 (112-9).
- Микрофону нужен HTTPS или localhost: в классе — профиль `compose.class.yaml` (ADR-033) с внутренним CA.
- Голосовой звонок с озвучкой заявителя (TTS) — 112-8b, отдельное решение.
