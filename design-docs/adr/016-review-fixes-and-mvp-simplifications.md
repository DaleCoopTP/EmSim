# ADR-016. Исправления второго ревью и упрощения первого этапа

Статус: accepted · 2026-09-18 · уточняет ADR-004/005/006/009/010/011/012/013/014; ADR-015 сохраняется

## Контекст
Согласованы исправления A1–A10 с уточнениями из ответа на ревью, а также B1–B5. Это явное изменение предыдущих требований к восстановлению и хранению промежуточных результатов. Текущий этап — ДДС, 112 позже с отдельной рубрикой.

| Пункт | Решение |
|---|---|
| A1, B1 | Нет heartbeat на строке занятия и компенсации часов. При startup до readiness открытые карточки получают interruption; timing not_applicable; overdue сообщения late. Серверные timestamps/deadlines не переписываются |
| A2 | Ручная оценка по evidence доступна без auto/input. Auto зарезервирован номер 1, первая expert без auto — номер 2/base 0. Ручная оценка отменяет evaluate; поздняя auto запрещена. Последняя ошибка/reaper при готовом input создаёт needs_review auto атомарно с терминальной задачей |
| A3 | needs_review/unavailable имеют score=NULL и passed=NULL. Не перенормируем unavailable в полноценный балл. Отчёты отдельно показывают незавершённые проверки |
| A4 | rubric.schema.json, kind=deterministic/llm, строковая версия, отдельные проверки заполненности отработки, её содержания и устного доклада. Адрес сравнивается по нормализованным компонентам, не общей похожести строк; неоднозначность требует проверки |
| A5 | Нет общего STT cutoff через 180 с: upload deadline для отсутствующего файла, терминальное состояние STT для загруженного. Таймаут одной попытки по замерам, ограниченные retries, ручная оценка при ожидании. STT после close |
| A6 | Coordinator — короткий цикл worker каждые 2 с, polling без LISTEN; waiting не расходует попытки |
| A7 | Обычный режим выдаёт следующую в close; hard — по next_offer_at без лимита двух карточек и без пачки просроченных выдач. spawn_card использует ту же назначенную очередь |
| A8 | set_status не закрывает; close допустим после терминального статуса при выполненных обязательных полях. Норматив не автозакрытие, timeout удалён |
| A9 | reference.critical_errors удалён; дефолтная критичность рубрики + scoring.critical |
| A10 | Debounce советов 5 с через state; dedup сохраняет basis_version; проверка свежести до LLM и перед публикацией. Приоритеты: оценка 100, генерация 50, совет 10 |
| B2 | Один assessment_inputs: правила, рубрика, тексты STT с происхождением, вход judge. Нет assessment_rule_results/call_transcripts/assessment.prepare. STT временно в tasks.result с удержанием до seal/отмены; отдельного раннего UI правил нет |
| B3 | Одна неподтверждённая команда на item в localStorage, аудио только в памяти. После закрытия вкладки незагруженная запись может потеряться; это показывается как missing, не как отсутствие звонка |
| B4 | stop_cutoff_log_seq на items; stop фиксирует его под барьером lessons до фонового закрытия |
| B5 | trainee_assessment_state(user_id,exercise_type) принадлежит assessment; users не содержит версии оценки. Смена уровня координирует порты auth/assessment в одной транзакции |

## Последствия
MVP не обещает сохранность незагруженных байтов микрофона при закрытии вкладки. Прерванные сервером карточки имеют timing not_applicable и исключены из рекомендации уровня; остальные применимые веса нормируются с видимой отметкой interruption. Это согласованное упрощение, не скрытый дефект.

Три роли, PostgreSQL-очередь, отдельные пулы, fencing, неизменяемый evidence, одна автооценка и приоритет преподавателя сохраняются. Постоянные task results нельзя удалять до фиксации их содержимого в assessment_inputs. Прямого вызова LLM из интерактивных команд нет.

## Приёмка
Проверить: ручную оценку без auto/input; одновременные expert и auto; терминальный сбой inference; NULL в needs_review; долгую очередь STT без отсечения; восстановление после restart без сдвига часов; close/планировщик без двойной выдачи; stop cutoff; приоритеты задач и пропуск устаревшего совета до LLM; replay из localStorage и явно потерянное аудио. Статические/SQL-тесты не заменяют будущие конкурентные тесты приложения.
