# ADR-012. Детерминированная рекомендация и актуальность совета

Статус: accepted · уточнён ADR-015/016 от 2026-09-18

## Решение
- Последние N=5 итоговых ready-оценок текущего учебного уровня и exercise_type, минимум 3; вверх при среднем ≥80 без критических ошибок, вниз при среднем <50 либо двух критических подряд. Intro/interrupted/interruptions/needs_review исключаются.
- Используются runs.level_at_start и difficulty версии сценария, не текущие значения профиля.
- Assessment владеет trainee_assessment_state(user_id,exercise_type,version,advice_due_at). Новая итоговая оценка меняет version и ставит детерминированную рекомендацию с этой версией в dedup в той же транзакции.
- Basis хранит assessment_id/revision, уровень, тип, политику. Проверка версии перед публикацией; применение требует id/basis_version. Application use case атомарно вызывает auth для уровня и assessment для версии состояния: users → trainee_assessment_state → остальные locks. Прямой записи assessment в auth-таблицы нет.
- Совет получает только агрегаты. Правка скрывает устаревший текст и переносит advice_due_at на now+5 секунд. Worker polling после затишья ставит задачу для текущей версии, с basis_version в dedup. Устаревшие задачи пропускаются до LLM и перед публикацией.
- Priority: оценка 100, генерация 50, совет 10. Уже выполняющийся inference не прерывается. Уникальный постоянный dedup без версии не используется.

## Последствия
Частые правки объединяются в один совет; старый результат не блокирует новые версии. PDF/CSV фиксируют конкретные основания и дату; SQL-отчёт отражает текущую итоговую оценку.
