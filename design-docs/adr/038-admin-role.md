# ADR-038. Роль администратора: журнал, нагрузка, отчёты, конфигурация, режим обслуживания, целостность, политика входа, обновление

Статус: accepted · 2026-09-29 · реализует часть 2 ДДС-10 (`slice-planning-dds.md`), общую для ДДС и 112; дополняет ADR-033, уточняет RFC-001 §9, §10 и ADR-008

## Контекст

В ТЗ заказчика для роли «Администратор системы» перечислены управление сервисами, мониторинг, отчётность, конфигурация, безопасность и ограничения администратора. Сверка с кодом на 29.09.2026.

Уже есть:
- пользователи всех ролей, назначение роли и службы, смена пароля, блокировка через `active` с отзывом сеансов, защита последнего админа (`internal/auth/admin.go`);
- рабочие места;
- экран «Состояние» (ADR-033): очередь задач, упавшие задачи с повтором, модель LLM, heartbeat воркеров, свободный диск, версия схемы, резервные копии по кнопке и ежедневно;
- журнал аудита: пишется в транзакции каждого эффекта, чистится `audit.prune`;
- ограничения администратора выполняются устройством ролей (`internal/auth/authz.go`): у `admin` нет доступа к сценариям, занятиям, оценкам и отчётам, а удалять данные он не может, только деактивировать.

Не хватает:
- журнал аудита нельзя прочитать иначе как SQL-запросом;
- нет нагрузки на сервер, статистики использования и отчёта о сбоях;
- параметры видны только в переменных окружения;
- нет уровня логов (RFC-001 §10 обещал его «по env»);
- нет контроля целостности;
- вход защищён только ограничением 5 попыток в минуту: нет блокировки учётки, смены выданного пароля, списка сеансов;
- нет массового создания пользователей;
- нет процедуры обновления, а `scripts/restore.sh` заменяет данные без страховочной копии;
- `/admin/import/*` описаны в `openapi.yaml`, но не реализованы.

## Решение

Решения пользователя от 29.09.2026 и их толкование.

### Что не делаем и почему

- **Запуск и остановка сервисов из веба — нет.** Для этого веб-процессу нужен docker socket, а это фактически root-доступ к серверу. Сервисы запускаются и останавливаются через `make`/`docker compose` по инструкции, состояние видно на «Состоянии». Вместо кнопок «стоп» есть **режим обслуживания**: он запрещает старт новых занятий и предпросмотров, идущие занятия доводятся до конца.
- **Настройка виртуальной IP-телефонии — пункт пропускается.** Реального SIP нет (ADR-005), экран и параметры под этот пункт не делаются.
- **Базовые настройки безопасности** (TLS, срок сессии, политика паролей и блокировки) задаются в `.env` на сервере. «Соответствующие права» — это доступ к хосту, а не роль в вебе. Роли суперадмина нет.
- **Конфигурация БД и остальные параметры** — только просмотр. Из интерфейса не меняются ни `DATABASE_URL`, ни другие переменные.
- **`/admin/import/classifier|tickets`** в контракте помечаются как нереализованные. Импорт остаётся в CLI (`emsim import`), формат ждёт ДДС-5.

### Что добавляем

- **Журнал аудита.** `GET /admin/audit` с фильтрами (период, пользователь, действие, результат, тип ресурса), keyset-пагинация по `id`, плюс `GET /admin/audit.csv`. Действующее лицо показывается логином через порт к `auth`, ФИО не выводятся. Сама выгрузка пишется в аудит. Неудачный вход по существующему логину пишет `resource_id` учётки.
- **Уровень логов и версия сборки.** `LOG_LEVEL` для api и worker. Версия сборки задаётся через `-ldflags`, видна для api и каждого воркера.
- **Нагрузка.** Скользящее окно за 5 минут в памяти api: запросы, 5xx, p50/p95, отдельно команды обучаемых. Плюс SSE-подключения, load/CPU/память хоста из `/proc`, активные сеансы, идущие занятия и открытые карточки, пулы воркеров, состояние STT.
- **Отчёты.** «Использование» (`GET /admin/usage`, модуль `reporting`): анонимные счётчики за период по дням, превью не учитываются. «Сбои» (`GET /admin/failures`): упавшие задачи по виду и коду, перезапуски, отклонённые входы, ошибки из аудита. Оба с CSV.
- **Конфигурация.** `GET /admin/config`: действующие значения по группам с именем переменной `.env` и процессом. Секреты не отдаются никогда. Worker публикует свой снимок в `platform_heartbeats` (`config.worker`).
- **Режим обслуживания.** Однострочная таблица `platform_maintenance` (миграция `00022`). `PUT /admin/maintenance`, `GET /system` для всех ролей. `training.Service.Start`/`StartPreview` читают строку `FOR SHARE` в своей транзакции, а переключение берёт её `FOR UPDATE`, поэтому старт не может проскочить после включения. Отказ — `409 maintenance_mode`.
- **Целостность.** Задача `integrity.check` (ежедневно и по кнопке) сверяет:
  - файлы `blobs` с их sha256 и размером;
  - `evidence.digest` и `scenario_versions.digest` с пересчётом канонического digest;
  - манифесты резервных копий;
  - версию схемы.

  Итог (счётчики и до 20 id расхождений, без содержимого) попадает на «Состояние» и в аудит.
- **Политика входа** (миграция `00023`: `users.failed_logins`, `locked_until`, `must_change_password`):
  - блокировка после `LOGIN_LOCKOUT_ATTEMPTS` неудач на `LOGIN_LOCKOUT_DURATION`, ответ `423 account_locked`;
  - минимальная длина пароля — `PASSWORD_MIN_LENGTH`;
  - `PASSWORD_FORCE_CHANGE` (по умолчанию `admin,instructor`) — роли, которые обязаны сменить пароль, выданный или сброшенный администратором. До смены middleware отвечает `403 password_change_required` на всё, кроме `/me`, `/me/password` и выхода;
  - администратор видит блокировку и сеансы пользователя, может разблокировать учётку и завершить все её сеансы.
- **Массовое создание пользователей.** `POST /admin/users/import` из CSV, всё или ничего, режим dry-run. Пароли генерирует сервер и отдаёт один раз в ответе. Они нигде не хранятся и не логируются.
- **Обновление без потери данных.** `scripts/update.sh`: обязательная копия → миграция → запуск → ожидание `/readyz`; при ошибке копии обновление останавливается. `restore.sh` перед заменой делает страховочную копию. `make release-bundle` сохраняет уже собранные образы без скачивания новых. `audit.prune` удаляет строки, только если есть успешная копия за последние 24 часа (когда бэкап настроен).

## Последствия

- Все новые ответы для администратора обходятся без ФИО курсантов, текстов, транскриптов и секретов. Статистика анонимна.
- Доступ администратора к содержимому занятий по-прежнему закрыт: `/admin/usage` — отдельный маршрут `GroupAdmin`, а не открытие отчётов преподавателя.
- Правка параметров требует доступа к серверу и перезапуска контейнеров — это осознанное ограничение.
- Нагрузочные показатели api живут в памяти процесса и сбрасываются при его перезапуске. Долгосрочную историю по-прежнему даёт Prometheus на `:8081`.
- Офлайн-пакет с весами моделей, нагрузочный прогон и W0 остаются техдолгом ДДС-10.
