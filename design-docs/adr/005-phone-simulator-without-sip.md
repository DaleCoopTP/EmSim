# ADR-005. Телефон — симулятор в браузере без SIP

Статус: accepted · 2026-09-17 · уточнён ADR-016 от 2026-09-18, Slice 5 от 2026-09-20

## Контекст
ТЗ: «IP-телефония через локальный SIP-сервер», «VoIP ≤ 150 мс». Q&A [10:17–11:05, 39:29–40:35]: «аппаратный телефон не нужен, симулятор на компьютере — в идеале; реальных вызовов не будет; набирает мышкой номер, слышит „Слушаю вас“, говорит, слышит „Информация принята“».

## Решение
Панель телефона в SPA: список контактов сценария (руководитель бригады, начальник смены, 112, УК) → набор → `action call_start` → воспроизведение заранее подготовленного `greeting` → `MediaRecorder` (webm/opus) → завершение записи и `ack` → поля отработки → `action call_end` с манифестом hash/размер/MIME → `PUT recording`. Файл и чанки находятся только в памяти вкладки; после её закрытия незагруженная запись теряется. Факт звонка и текст отработки остаются на сервере; критерий устного доклада при потере записи unavailable. Поздняя загрузка до `closed_at + recording_grace_s` допускает только объявленный файл; повтор принятого файла идемпотентен даже после срока, замена запрещена (ADR-014). Голос и интонация — атрибуты контакта в сценарии; в Slice 5 подготовленные реплики импортируются административной CLI из immutable manifest, без TTS-задачи.

`call_start`/`call_end`, действие, audit, `seq`/`log_seq` и строка звонка фиксируются одной транзакцией. На карточке допускается лишь один незавершённый звонок. Обязательный звонок с требуемым контактом должен быть завершён до указанного в эталоне статуса и до закрытия; незавершённый звонок блокирует close. Rejection-коды: `call_required`, `call_in_progress`, `call_not_active`; неизвестный контакт и неверный recording manifest — `invalid_payload`.

Файлы имеют content-addressed хранение по SHA-256 под `BLOB_ROOT`. PostgreSQL хранит только метаданные и immutable связи. Для upload принимаются WebM/Ogg/WAV с проверкой заявленного MIME, размера, SHA-256 и magic bytes; клиентское имя и путь никогда не используются. Состояние записи: `absent`, `awaiting`, `ready`, `expired`; `expired` показывается пользователю как `missing`. Evidence фиксирует звонок и объявленный manifest на момент закрытия и не меняется поздним upload.

Доступ: обучаемый получает только phrase своего item; запись может скачать только преподаватель-владелец занятия и только после closed/interrupted. Администратор, другой преподаватель и обучаемый запись не получают.

Порт `Telephony` в коде оставлен узким (контакты, фраза по ключу), чтобы SIP-адаптер мог появиться позже без изменения домена.

## Варианты
- Asterisk + WebRTC (browser-phone) — два сервиса, кодеки, NAT в классе, ноль пользы для оценки; отвергнуто.
- Только текстовый «звонок» (без микрофона) — теряем оценку доклада и «похожесть»; отвергнуто как основной, оставлен как fallback при отсутствии микрофона.

## Последствия
- Нужен микрофон на РМ и разрешение браузера; без него звонок фиксируется как факт без записи.
- STT записи — фоновая задача только после закрытия карточки; результат временно удерживается в tasks.result и затем целиком копируется в assessment_inputs; критерий содержания доклада может быть `unavailable`.
- Строки ТЗ про SIP/150 мс — roadmap-профиль в документации.
