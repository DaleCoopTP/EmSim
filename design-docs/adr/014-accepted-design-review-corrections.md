# ADR-014. Согласованные исправления design review

Статус: accepted · 2026-09-18

Последующие изменения: [ADR-016](016-review-fixes-and-mvp-simplifications.md) заменяет описанные ниже компенсацию часов, IndexedDB/аудиобуфер, промежуточные таблицы оценки, расположение cutoff и версии основания. Он также разрешает ручную оценку без auto и NULL-балл для needs_review. Таблица ниже — история прежнего решения, не инструкция реализации этих заменённых частей.

Уточнение области действия: последующий [ADR-015](015-dds-first-operator112-extension.md) включает оператора 112 в общий объём следующим этапом после ДДС. Ниже сохранён контекст предыдущего ревью; исключение 112 более не является общим ограничением проекта.

## Контекст и граница
В обсуждении 17–18 сентября согласованы пункты 1, 4, 5, 7, 8, 9, 10, 11, 12 ревью. Это уточнение действующего MVP ДДС; устаревшая архитектура `docs/` и режим оператора 112 не возвращаются в скоуп. ADR-014 заменяет противоречащие ему части ADR-003/004/005/006/007/010/011/012; базовые решения монолита, PostgreSQL, SSE и моделей вне учебного цикла сохраняются. Связанные ADR обновлены для согласованного чтения.

## Что не добавляем этой правкой
- Пункт 2: сохраняем общий набор критериев, дефолтные веса + reference.scoring, два оценщика по kind. Новую формулу и полные рубрики на кейс не вводим; пересмотр конкретного набора критериев не входит в эту правку.
- Пункт 3: пустое обязательное поле — 0; расширенную математику unavailable/частичных оценок отложили. Ранее предусмотренный needs_review остаётся техническим статусом, новых шкал и coverage-score нет.
- Пункт 6: развитие дублей — второстепенный backlog, отдельный алгоритм поиска дублей не добавляем. Сам hard с несколькими открытыми карточками сохраняется.
- Дополнительный список security/экспортов/backup/миграций отложен; из него фиксируется только подтверждённая периодичность backup: не реже одного раза в сутки. PDF уже обязателен по актуальному контексту.

## Последствия и приёмка
Документы и исполняемые схемы уточняются до начала реализации. JSON/DDL-проверки подтверждают структуру и ограничения; они не доказывают работу будущего Go-кода. При реализации обязательны конкурентные проверки: replay после stop, закрытие против доставки, потеря lease до finalize, падение после commit, поздняя запись с тем же/другим hash, reconnect между snapshot и событием, stop при занятом LLM-пуле. В check.py добавлены отрицательные контракты; SQL-инварианты проверяются отдельно на чистой временной БД.
