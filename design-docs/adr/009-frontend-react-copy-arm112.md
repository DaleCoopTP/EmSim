# ADR-009. React + TypeScript, копия АРМ-112 без UI-кита

Статус: accepted · 2026-09-17 · уточнён ADR-016 от 2026-09-18

## Контекст
Заказчик [25:24]: «точно копировать рабочую программу, привязаться к шаблону, меньше самодеятельности»; экраны — в памятке (стр. 12–18, 24). Жюри — эксперты УМЦ, узнают интерфейс. Три роли в одном приложении; push по SSE; запись микрофона.

## Решение
- SPA: React 18 + TypeScript + Vite; данные — TanStack Query; формы — нативные; push — `EventSource`; аудио — `MediaRecorder` и `<audio>`.
- Без UI-кита (MUI/Ant): экраны верстаются по скриншотам АРМ-112 (плотная таблица карточек, панель списка оповещения с «карандашом» статусов, серые Windows-подобные формы). Единый файл токенов (цвета, шрифты, отступы), взятый с референса.
- Типы API — из `openapi.yaml` (`openapi-typescript`); клиент — тонкий fetch-wrapper с `X-Request-ID` и повтором команд по `command_id`.
- localStorage хранит одну неизменяемую неподтверждённую команду на item с ключом user/item. После reconnect сначала восстанавливаются квитанции; чужая учётка эти команды не отправляет. Аудио только в памяти: сетевой обрыв при живой вкладке допускает повтор upload, закрытие вкладки может потерять незагруженные байты (ADR-016).
- Сборка кладётся в бинарник (`embed`) — один артефакт поставки.
- Ознакомительный режим — тот же набор компонентов + слой подсказок (`data-hint` + оверлей), не отдельное приложение.

## Варианты
- Vue/Svelte — не хуже, но React у команды под рукой; отвергнуто без спора.
- UI-кит — быстрее «красиво», но дальше от АРМ-112; отвергнуто.
- Server-rendered (templ/HTMX) — таймеры, телефон, монитор проще на клиенте; отвергнуто.

## Последствия
- Верстка по референсу — заметная доля W2; скриншоты запросить у заказчика дополнительно.
- Мобильная версия — не делается (N6); layout фиксирован под 1366+ px.
