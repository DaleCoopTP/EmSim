# Объём задачи 9 — сверка трёх источников

Источники: страница кейса на i.moscow, ТЗ (PDF), сессия Q&A (видео, см. `qa-session-summary.md`), памятка АРМ-112.

## Почему источники расходятся

Заказчик — УМЦ ГО ЧС (учебный центр), не ГБУ «Система 112». Они обучают диспетчеров ДДС города, которые за АРМ-112 *получают* карточки, а не операторов 112, которые звонки *принимают*.

- Сайт: обобщённо «обучать операторов системы 112, эмуляция вызова на гарнитуру», но в «Актуальности» — «диспетчерский персонал ДДС», «информация из 112 передаётся на АРМ ДДС».
- ТЗ: сценарий 1 (звонок → заполнение карточки) — работа оператора 112; сценарий 2 (действия с карточками, текст «Сообщение принято, дежурная бригада направлена») — работа диспетчера ДДС.
- Видео: оставлен только сценарий 2; звонок перевёрнут — исходящий от диспетчера руководству; сценарий 1 — «на следующий год».

## Что симулируем

Рабочее место диспетчера ДДС на АРМ-112: в службу приходит карточка происшествия из системы-112, диспетчер её отрабатывает. Одна задача, один режим. «112» и заявителя заменяют преподаватель + ИИ, формирующие карточки заранее.

## Действия обучаемого (одна карточка)

1. Новое сообщение в списке карточек (номер, время, тип, адрес, статус). Таймер.
2. Открыть карточку — норматив 30 с. Автостатус «Получена службой».
3. Прочитать: адрес, заявитель, признаки/итоговый тип, описание, список оповещения со статусами других служб.
4. Первичное решение: «Принята» / «Не принята» + обязательный комментарий (причина, куда передано). Компетенция, территория, дубль.
5. Реагирование статусами: Начало реагирования → Прибытие → Проведение работ → Работы завершены, либо Отказ + комментарий. События «выехали/прибыли» подаёт сценарий (текст/голосовое сообщение от «бригады»).
6. Звонок по симулятору IP-телефона руководству/другой службе: номер → «Слушаю вас» → доклад → «Информация принята». Речь записывается.
7. Исправления по памятке: Не принята → Принята; ошибочно Принята → Отказ с комментарием; после завершения — «Сообщить в отдел контроля».
8. Закрытие («Работы завершены» закрывает редактирование). Норматив на отработку — 3 мин. Следующая карточка до завершения занятия.

Профиль обучаемого = служба; получает только карточки со своей службой в списке оповещения. 3–5 приоритетных служб, расширение через данные.

## Что оцениваем

| Критерий | Проверка | Источник |
|---|---|---|
| Время | открыл ≤ 30 с; первичный статус ≤ 30 с от направления; отработал ≤ 3 мин; превышение в отчёте | видео, ТЗ |
| Первичное решение | совпадает с эталоном (компетенция/территория/дубль); отказ от профильного — критическая ошибка | памятка, нарушения 2–3 |
| Наличие статуса | без первичного статуса → «Не оповещено» | нарушение 1 |
| Комментарий | обязателен при Не принята/Отказ; причина + куда передано; при работах — уточнения | нарушения 4–6 |
| Последовательность | статусы соответствуют событиям сценария; недопустимые переходы блокирует UI, пропущенные — штраф | памятка стр. 25 |
| Грамматика/адреса | опечатки в ручном тексте; искажение адреса — критическая ошибка | видео |
| Звонок | сделан, когда требовался; в речи адрес, тип, меры (STT по записи) | видео, нарушение 7 |
| Итог | взвешенная сумма, сложность 1–10, порог; ИИ подсвечивает, преподаватель подтверждает/правит | видео |

LLM-judge нужен только для содержательной полноты комментария и содержания доклада; работает после завершения карточки.

## Преподаватель

Генерирует карточки заранее (билеты + классификатор + LLM), утверждает, ставит сложность; раздаёт задания по рабочим местам галочками; старт/стоп занятия; live-монитор; подтверждает/правит оценку ИИ; отчёт (ФИО, номер РМ, балл, время, ошибки, уровень; таблицы/графики); рекомендация следующего уровня.

## Не делаем

- Входящий звонок заявителя и заполнение карточки с нуля (сценарий 1 ТЗ) — снято заказчиком; максимум слайд roadmap.
- Интерактивный голосовой диалог, real-time STT, Asterisk.
- LLM в цикле обучаемого: генерация — до занятия, оценка — после карточки.
