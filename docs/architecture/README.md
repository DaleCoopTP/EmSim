# EmSim: архитектура системы обучения операторов ДДС

Версия 1.0 · 16 сентября 2026 · статус: проект для архитектурного ревью.

**Решение:** модульное Go-приложение с отдельными процессами API, фоновых исполнителей и media gateway; PostgreSQL как источник истины; локальные LLM/STT/TTS и SIP-сервер. Из orchestration core переносится механизм надёжного выполнения, а интерактивная учебная модель создаётся отдельно.

Это проект системы, а не утверждение, что она уже реализована или прошла нагрузочные испытания. Все 26 строк `additional_requirements.md` считаются обязательными. Колонка «Что предлагаем» трактуется как предложенный способ выполнения: при конфликте с ТЗ выбирается способ, который выполняет само требование.

## С чего начать

1. Открыть [визуальный атлас](architecture-atlas.html): контексты, компоненты кода, два учебных потока, остановка, данные и размещение. Файл автономный, работает без интернета.
2. Прочитать [архитектурное решение](01-system-design.md): домен, инварианты, поведение и обоснование.
3. Сопоставить [матрицу требований](03-requirements.md) с исходным `additional_requirements.md`.
4. Посмотреть [что переносим из core](02-core-reuse.md), затем [контракты](04-contracts.md) и [данные и транзакции](05-data-and-consistency.md).
5. Использовать [декомпозицию реализации и приёмку](06-delivery-and-validation.md) для составления полного инженерного плана. [ADR и вопросы для защиты](07-decisions.md) объясняют компромиссы.

## Ключевые разграничения

- `Lesson` — занятие преподавателя; `Assignment` — назначение оператору; `TrainingRun` — его попытка; `RunItem` — одна карточка/кейс в попытке; `Task` — короткая техническая работа.
- Статус занятия, статус прохождения, статус оценки, статус карточки и статус реагирования службы — разные состояния.
- Завершённое прохождение может ещё оцениваться. Технический сбой judge не является плохой оценкой оператора.
- PostgreSQL хранит подтверждённые данные; очередь браузера хранит ещё не подтверждённые. SSE и память worker не являются хранилищем.
- 150 мс относятся к передаче аудио. Время ответа LLM/STT/TTS измеряется отдельно. Асинхронный HTTP-ответ сам по себе не доказывает отклик интерфей]са за 2 секунды.

## Источники и приоритет

1. [Дополнительные требования](../../additional_requirements.md), 26 строк, обязательны по текущему поручению.
2. [ТЗ](../../9.%20ТЗ_Деп%20Обороны%20и%20ЧС.pdf), 20 страниц PDF. В документах этого пакета используется **номер страницы PDF**, а не напечатанный номер (у ТЗ они отличаются на единицу).
3. [DDD context map](../../emergency_chat_ddd_context_map.excalidraw) и [тактическая схема](../../emergency_chat_ddd_ru.excalidraw).
4. Памятка АРМ-112, 40 страниц; предметные правила преимущественно на страницах 8, 14–27, 32–33. Памятка сама оговаривает, что не является официальной инструкцией: неоднозначные переходы должны пройти валидацию преподавателем.
5. XLSX-классификатор: `Лист1`, заявленные размеры листа 1310 строк × 104 столбца; это размеры листа, **не количество типов происшествий**. Заголовки в строках 1–3, комбинации признаков и итоговый тип в G–L, маршрутизация и условия служб далее.
6. [Исходный orchestration core](../../orchestration-core-main/README.md), проверен по коду и SQL, не только README.

Параметры и решения, которых нет в источниках, явно обозначены как проектные. Нормативные документы, перечисленные в ТЗ, не интерпретируются здесь как заключение о юридическом соответствии.
