# Развёртывание и эксплуатация

## 1. Требования

| | Демо на ноутбуке | Сервер класса |
|---|---|---|
| ПО | Docker с Compose v2 | Docker с Compose v2 (проверено на Ubuntu 24.04) |
| CPU / ОЗУ | без моделей — любой современный ноутбук; с моделью — от 8 ГБ памяти для Docker | ориентир 6+ ядер, 32 ГБ; GPU не требуется. Ёмкость класса с ИИ-заявителем см. в [status.md](status.md#2-замер-производительности-модели) |
| Диск | ~2 ГБ образы, ~6 ГБ веса моделей | то же плюс место под резервные копии |
| Сеть | интернет только для первой сборки и загрузки весов | локальная сеть класса; интернет не нужен |
| Браузеры РМ | Chrome, Edge, Яндекс Браузер актуальных версий | то же; для диктовки — HTTPS |

## 2. Состав стека

`docker compose up` поднимает:

| Сервис | Что делает |
|---|---|
| `postgres` | PostgreSQL 16 — данные и очередь задач |
| `migrate` | одноразово: применяет миграции |
| `bootstrap` | одноразово: создаёт администратора из `BOOTSTRAP_ADMIN_LOGIN` / `BOOTSTRAP_ADMIN_PASSWORD` (идемпотентно) |
| `seed` | одноразово: загружает службы, классификатор, каталог 112 и сценарии из `seed/` (идемпотентно) |
| `api` | веб-клиент и API на порту `8080`; служебные `/healthz`, `/readyz`, `/metrics` на `8081` |
| `worker` | фоновые задачи; служебный порт `8082` |
| `llm` | `llama-server` с моделью T-lite-it-2.1 (Q5_K_M); во внутренней сети, без опубликованного порта |
| `stt` | `whisper-server` для диктовки оператора 112; во внутренней сети |

Образы моделей закреплены по digest. Веса не хранятся ни в git, ни в образе — они читаются из каталога `./models`.

Профили — дополнительные compose-файлы поверх `compose.yaml`:

| Файл | Назначение |
|---|---|
| `compose.no-llm.yaml` | без моделей: ИИ-заявитель — заглушка, ИИ-судья и диктовка выключены. Так работают e2e и CI |
| `compose.class.yaml` | сервер класса: Caddy с HTTPS от внутреннего CA перед `api` |
| `compose.public.yaml` | публичный стенд: Caddy с сертификатом Let's Encrypt (поверх профиля класса) |
| `compose.remote-llm.yaml` | внешний OpenAI-совместимый API вместо локальной модели |

## 3. Локальный запуск

```bash
cp .env.example .env        # сменить пароли администратора и БД
make model                  # веса языковой модели в ./models (один раз)
make stt-model              # модель распознавания речи (один раз)
docker compose up --build
```

Откройте http://localhost:8080 и войдите администратором. В демо-профиле `api` слушает только `127.0.0.1` и работает без HTTPS (`COOKIE_SECURE=false`); для доступа с других ПК используйте профиль класса.

Без моделей:

```bash
docker compose -f compose.yaml -f compose.no-llm.yaml up --build
```

Сборка образа включает сборку веб-клиента: он встраивается в бинарник `emsim`, отдельный веб-сервер не нужен.

`make seed` перезапускает только загрузку каталога — например, после добавления файла в `seed/scenarios/`.

### Демо-пользователи

На запущенном стеке:

```bash
DEMO_PASSWORD=<пароль не короче 8 символов> make demo
```

Создаются рабочие места `РМ-01…РМ-N` (`DEMO_WORKSTATIONS`, по умолчанию 6), преподаватель `instructor` и обучаемые `trainee01`, `trainee02`, … по одному на РМ. Упражнения распределяются по кругу: ДДС района, ДДС 03, оператор 112. Повторный запуск добавляет только недостающее и не меняет существующие пароли.

## 4. Модели

### Языковая модель

ИИ-заявитель и ИИ-судьи работают через сервис `llm` — `llama-server` из llama.cpp с моделью T-lite-it-2.1 8B в формате GGUF Q5_K_M (~5,4 ГБ).

```bash
make model                                # из реестра Ollama (по умолчанию)
scripts/fetch-model.sh --from-ollama      # копия из локального Ollama без скачивания
scripts/fetch-model.sh --url <URL.gguf>   # любой адрес; нужен LLM_MODEL_SHA256
```

Каждый способ проверяет sha256 файла. Проверенное значение закреплено в `scripts/fetch-model.sh`, другой файл скрипт не установит.

Без файла модели `llm` не проходит проверку здоровья и `worker` не запускается: отсутствие модели видно при установке, а не на занятии.

Разработка с Ollama на хосте (например, Mac с GPU):

```bash
ollama serve
ollama pull t-tech/T-lite-it-2.1:q5_K_M
CALLER_REPLIER=llm ASSESSMENT_JUDGE=llm \
  docker compose -f compose.yaml -f compose.no-llm.yaml up --build
```

**Память.** С настройками по умолчанию `llama-server` занимает около 7,2 ГБ: веса, переупакованные под CPU (~4,7 ГБ), и кэш контекста (~2,4 ГБ). Для сервера с 32 ГБ это нормально. В Docker Desktop с 8 ГБ модель может падать при загрузке по нехватке памяти (в логе обрыв на `load_model`, контейнер перезапускается по кругу). Тогда задайте в `.env`:

```bash
LLM_REPACK=false
LLM_PARALLEL=1
LLM_CTX_SIZE=4096
CALLER_CONCURRENCY=1
```

**Прогрев.** Когда оператор отвечает на вызов и когда пишет первую фразу, система заранее отправляет модели известное начало промпта, и `llama-server` кладёт его в кэш. Первый ответ заявителя от этого приходит быстрее. Прогрев не влияет на данные занятия; выключается `CALLER_WARMUP=false`.

**Замер производительности** на поднятом стеке:

```bash
docker compose run --rm worker bench-llm --concurrency 1,4,8,20 --duration 2m --judge 1
```

Виртуальные операторы ведут многоходовые диалоги по ИИ-сценариям через тот же код, что и `worker`. Отчёт по каждому уровню параллельности: ответы в минуту, p50/p95/p99 задержки ответа заявителя, доля ответов дольше таймаута, ошибки, задержка судьи, скорость генерации. `scripts/server-bench.sh` прогоняет замер по нескольким сочетаниям `LLM_THREADS` и `LLM_PARALLEL` и добавляет время распознавания речи.

### Распознавание речи

Диктовка оператора 112 работает через сервис `stt` — `whisper-server` из whisper.cpp с моделью `ggml-small` (~465 МБ).

```bash
make stt-model
# точнее, но тяжелее для CPU:
STT_MODEL_FILE=ggml-large-v3-turbo-q5_0.bin make stt-model
```

Браузер даёт доступ к микрофону только по HTTPS или на `localhost`, поэтому в классе нужен профиль `compose.class.yaml` с установленным корневым сертификатом. Если `stt` недоступен, диктовка отвечает ошибкой, а печать работает.

Образ whisper.cpp собран только для `linux/amd64`; под эмуляцией Docker на Apple Silicon он зависает. На Mac запускайте `whisper-server` нативно и укажите его адрес:

```bash
build/bin/whisper-server -m models/ggml-small.bin -l ru --host 127.0.0.1 --port 8090
DICTATION=whisper STT_URL=http://host.docker.internal:8090 \
  docker compose -f compose.yaml -f compose.no-llm.yaml up --build
```

### Удалённая модель

Если сервер не тянет локальную модель, ИИ-заявитель и судья подключаются к внешнему OpenAI-совместимому API, а сервис `llm` не запускается:

```bash
REMOTE_LLM_URL=https://llm.example/v1 REMOTE_LLM_MODEL=<модель> LLM_API_KEY=<ключ> \
  docker compose -f compose.yaml -f compose.remote-llm.yaml up -d --build
```

- Ключ передаётся заголовком `Authorization: Bearer` и не попадает в логи. Храните его в `.env`.
- Разные ключи для заявителя и судьи — `CALLER_LLM_API_KEY`, `JUDGE_LLM_API_KEY`; другая модель для судьи — `REMOTE_JUDGE_MODEL`.
- `LLM_DIALECT=openai` отправляет только стандартные поля; для удалённого `llama-server` или Ollama — `LLM_DIALECT=llama`.
- Реплики разговора и тексты описаний при этом уходят за пределы учебного центра. Включайте режим только там, где это согласовано.

## 5. Сервер класса

Профиль `compose.class.yaml` ставит перед `api` Caddy. Caddy — единственный сервис, доступный из локальной сети (порты 443 и 80 с редиректом на HTTPS); сертификат выпускает его внутренний CA; cookie сессии получает флаг `Secure`.

1. В `.env` задайте имена и адреса, по которым РМ будут открывать сервер, например `EMSIM_HOST=emsim.local, 192.168.10.5`.
2. Запустите стек: `make class-up` (без модели — добавьте `-f compose.no-llm.yaml` перед `compose.class.yaml`).
3. `make class-ca` выгрузит корневой сертификат в `./emsim-root.crt`. Установите его на каждый ПК класса как доверенный корневой: в Windows — в «Доверенные корневые центры сертификации», в Firefox — отдельно в хранилище браузера.
4. На РМ откройте `https://<EMSIM_HOST>/`.

Сертификат CA хранится в томе `caddy-data`; не удаляйте его при обновлении, иначе сертификат придётся ставить на ПК заново. Если порт 443 занят, задайте `HTTPS_PORT`.

## 6. Публичный стенд

Для сервера с настоящим DNS-именем `compose.public.yaml` выпускает сертификат Let's Encrypt, ставить корневой сертификат на ПК не нужно.

1. A-запись имени указывает на статический IP сервера, входящие порты 80 и 443 открыты.
2. В `.env`: `EMSIM_HOST=emsim.example.org`.
3. `make public-up`.

Развёртывание на чистой Ubuntu 24.04: `scripts/server-sync.sh user@host` копирует проект без весов и секретов, затем на сервере `scripts/server-bootstrap.sh` ставит Docker, создаёт `.env` со случайными паролями, скачивает модели, поднимает стек и демо-пользователей.

## 7. Резервное копирование

Worker каждый день в `BACKUP_AT` (по умолчанию 03:00 по `SCHEDULE_TZ`, Europe/Moscow) делает копию в каталог хоста `BACKUP_HOST_DIR` (`./backups`) и хранит последние `BACKUP_KEEP` (14) копий. Копия — каталог `emsim-ГГГГММДД-ЧЧММССZ`:

- `db.dump` — `pg_dump` базы;
- `blobs.tar.gz` — аудиофайлы и отчёты;
- `manifest.json` — контрольные суммы, размеры, версия схемы.

Каталог копий стоит смонтировать на сетевой диск: копия на том же диске не спасёт от его отказа.

```bash
docker compose run --rm --no-deps worker backup     # копия сейчас
scripts/restore.sh backups/emsim-20260928-000000Z   # восстановление
```

`scripts/restore.sh` спрашивает подтверждение, делает страховочную копию текущего состояния, останавливает `api` и `worker`, сверяет контрольные суммы, заменяет базу и файлы, применяет миграции и поднимает стек. Копию от более новой версии EmSim он не восстанавливает. Для профиля класса: `COMPOSE="docker compose -f compose.yaml -f compose.class.yaml" scripts/restore.sh …`.

Ежедневно в `AUDIT_PRUNE_AT` (04:00) удаляются записи журнала аудита старше `AUDIT_RETENTION_DAYS` (183 дня) — только если есть полная копия не старше суток. В 05:00 выполняется проверка целостности: файлы, дайджесты снимков и версий сценариев, последняя копия, версия схемы.

## 8. Обновление

```bash
scripts/update.sh                      # образы собираются из этого каталога
scripts/update.sh emsim-release.tar    # офлайн, из пакета make release-bundle
```

Порядок для класса:

1. На экране «Состояние» включите режим обслуживания: новые занятия не стартуют, идущие продолжаются. Дождитесь их окончания.
2. Запустите `scripts/update.sh`. Первым делом он делает резервную копию; если она не удалась, ничего не меняется.
3. Если новая версия не стала здоровой, восстановите копию из шага 2 через `scripts/restore.sh`.
4. Выключите режим обслуживания.

`make release-bundle` собирает архив с образами, уже имеющимися на машине сборки, compose-файлами и скриптами. Веса моделей в архив не входят — их переносят отдельно.

Скрипты обновления и офлайн-пакета пока проверены только на синтаксис, прогона на чистом сервере не было.

## 9. Настройки

Все параметры задаются в `.env` (образец — `.env.example`) и применяются `docker compose up -d`. Действующие значения администратор видит на экране «Конфигурация».

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `POSTGRES_PASSWORD` | — | пароль БД |
| `BOOTSTRAP_ADMIN_LOGIN`, `BOOTSTRAP_ADMIN_PASSWORD` | `admin` / демо-пароль | первый администратор; пароль обязательно сменить |
| `API_PORT`, `API_ADMIN_PORT`, `WORKER_ADMIN_PORT` | 8080, 8081, 8082 | порты на хосте |
| `EMSIM_HOST`, `HTTPS_PORT`, `HTTP_PORT` | — , 443, 80 | имя сервера и порты для профилей класса и публичного стенда |
| `LOGIN_LOCKOUT_ATTEMPTS`, `LOGIN_LOCKOUT_DURATION` | 10, 15m | блокировка после серии неверных паролей |
| `PASSWORD_MIN_LENGTH` | 8 | минимальная длина пароля |
| `PASSWORD_FORCE_CHANGE` | `admin,instructor` | роли, которые должны сменить пароль, выданный администратором (`none` — никто) |
| `CALLER_REPLIER` | `llm` | `llm` — ИИ-заявитель, `stub` — заглушка из шести фраз |
| `ASSESSMENT_JUDGE` | `llm` | `llm` — ИИ-судья включён (рубрики v3), `off` — выключен (v2); должно совпадать в `api` и `worker` |
| `DICTATION` | `whisper` | `whisper`, `stub` (для тестов), `off` |
| `LLM_PARALLEL`, `LLM_CTX_SIZE`, `LLM_THREADS`, `LLM_REPACK` | 4, 16384, 6, true | параметры `llama-server` |
| `CALLER_CONCURRENCY`, `LLM_CONCURRENCY` | 3, 1 | одновременные запросы заявителя и судьи; в сумме не больше `LLM_PARALLEL` |
| `CALLER_REPLY_TIMEOUT` | 30s | ожидание одного ответа модели |
| `CALLER_WARMUP`, `CALLER_OPENING_DELAY` | true, 0s | прогрев кэша и задержка вступления заявителя |
| `STT_MODEL_FILE`, `STT_TIMEOUT`, `DICTATION_CONCURRENCY`, `DICTATION_MAX_SECONDS` | `ggml-small.bin`, 15s, 2, 30 | распознавание речи |
| `REMOTE_LLM_URL`, `REMOTE_LLM_MODEL`, `LLM_API_KEY`, `LLM_DIALECT` | — | удалённая модель |
| `SCHEDULE_TZ` | Europe/Moscow | часовой пояс ежедневных задач |
| `BACKUP_HOST_DIR`, `BACKUP_KEEP`, `BACKUP_AT` | `./backups`, 14, 03:00 | резервные копии |
| `AUDIT_RETENTION_DAYS`, `AUDIT_PRUNE_AT` | 183, 04:00 | хранение журнала аудита |
| `DEMO_PASSWORD`, `DEMO_WORKSTATIONS` | — , 6 | демо-пользователи |

## 10. Первичная настройка вручную

Без `make demo`:

1. Войдите администратором.
2. «Рабочие места» — добавьте РМ.
3. «Пользователи» — создайте преподавателя и обучаемых по одному или загрузите CSV. Обучаемому ДДС укажите службу: `dds_district_chertanovo` (ДДС района) или `dds_ambulance_03` (скорая 03). Обучаемому 112 служба не нужна.
4. Преподаватель входит, открывает «Сценарии» и «Занятия».
5. Обучаемый входит с номером своего РМ.

То же через API:

```bash
curl -c cookies.txt -X POST http://localhost:8080/api/v1/auth/login \
  -H 'Content-Type: application/json' -d '{"login":"admin","password":"<пароль>"}'
curl -b cookies.txt -X PUT http://localhost:8080/api/v1/admin/workstations \
  -H 'Content-Type: application/json' -d '[{"number":5,"label":"РМ-05"}]'
curl -b cookies.txt -X POST http://localhost:8080/api/v1/admin/users \
  -H 'Content-Type: application/json' \
  -d '{"login":"trainee05","password":"<пароль>","full_name":"Иванов Иван","role":"trainee","service_code":"dds_district_chertanovo"}'
```
