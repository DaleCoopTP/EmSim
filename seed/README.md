# Каталог и сценарии (`seed/`)

Готовые данные, которые загружаются в систему при первом запуске (`docker compose up` выполняет это сервисом `seed`). Все сценарии учебные: адреса, заявители и происшествия вымышлены или обезличены, оповещение служб происходит только внутри тренажёра.

## 1. Файлы

| Файл | Что содержит |
|---|---|
| `services.json` | справочник служб и workflow их статусов |
| `classifier.json` | строки классификатора происшествий заказчика: код, наименование, признаки, какие службы оповещаются |
| `intake-catalog.json` | каталог 112: типы происшествий, профильные опросные карты 101, 103, 104, правила подбора служб |
| `scenarios/*.json` | сценарии, по одному файлу на версию |
| `voice-assets/` | записанные фразы контактов (WAV, моно, 16 бит, 16 кГц) и их манифест |

### Службы

| Код | Служба | Для чего |
|---|---|---|
| `dds_district_chertanovo` | ДДС района Чертаново Южное | служба обучаемого ДДС: «Принята» / «Не принята», затем «Начало реагирования» → «Прибытие» → «Проведение работ» → «Работы завершены» или «Отказ». Комментарий обязателен для «Не принята» и «Отказ» |
| `dds_ambulance_03` | диспетчерская скорой помощи (03) | служба обучаемого ДДС; вместо «Не принята» и «Отказ» — «Завершение работ без бригады» |
| `pilot_fire_101`, `pilot_gas_104`, `pilot_ambulance` | учебные адресаты оповещения 112 | службы, которые оповещает оператор 112 |
| `dds_district`, `pilot_yuao_prefecture`, `pilot_nature_department` | службы ранних пилотов | только для архивных сценариев |

Импорт проверяет workflow службы: финальные статусы не имеют переходов и достижимы из начального. Workflow уже загруженной службы изменить нельзя — новая версия правил вводится новым кодом.

### Каталог 112

Каталог версионирован; версия фиксируется в занятии при старте, поэтому его обновление не меняет идущие занятия.

- Карта **104** (газовая служба): признаки запаха газа.
- Карта **101** (пожарная охрана): вопросы ветвятся по «Где» — улица, транспорт, дом, здание или объект.
- Карта **103** (скорая помощь): место вызова и данные пострадавшего — ФИО, дата рождения, возраст, пол.
- Типы: «Запах газа», «Пожар», «Возгорание мусора», «Возгорание транспорта», «Плохо человеку», «Травма» и ранние пилотные типы.
- Правила подбора служб: тип и карта предлагают службу (например, карта 103 → 03). Оператор может добавить или снять службу с причиной.

Карты составлены по снимкам интерфейса АРМ-112 от заказчика ([docs/reference-ui](../docs/reference-ui/README.md)); ветка «Здание / объект» карты 101 и верх списка «Место вызова» карты 103 восстановлены командой по аналогии и ждут проверки экспертом.

### Архивные сценарии

13 сценариев ранних этапов помечены `"archived": true`: пилоты «Дерево во дворе» с правкой округа, первый звонок бригаде, события по таймлайну, первые вызовы 112 с подготовленными вопросами, кейсы 112 без разговора и технический чат с заглушкой. Каталог их не показывает (фильтр «Архив» показывает), но прошлые занятия и оценки по ним читаются, а интеграционные тесты используют их для проверки обратной совместимости.

## 3. Формат сценария

Файл сценария описан схемой [scenario-file.schema.json](../design-docs/contracts/scenario-file.schema.json), тело — [scenario.schema.json](../design-docs/contracts/scenario.schema.json). Основные поля:

```json
{
  "schema": "emsim/scenario-file/v1",
  "key": "dds-district-tree-cycle-01",
  "version": 2,
  "title": "ДДС района: дерево перекрыло проезд — полный цикл реагирования",
  "body": {
    "exercise_type": "dds_processing",
    "target_service": "dds_district_chertanovo",
    "difficulty": 2,
    "card": { "number": "882107", "applicant": {…}, "address": {…}, "incident": {"type_code": "14080106", …}, "notification_list": […] },
    "contacts": [ {"key": "crew_leader", "role": "crew", "label": "Руководитель аварийной бригады", "phrases": {"greeting": "…", "ack": "…"}} ],
    "events": [ {"key": "e2", "since": "call_ended", "since_contact": "crew_leader", "at_s": 35, "delivery": "phone_incoming",
                 "text": "Диспетчер, это бригада. Мы на месте…", "expects": {"status": "arrived", "within_s": 30}} ],
    "reference": { "primary_decision": {"status": "accepted"}, "expected_chain": […], "call": {…} }
  }
}
```

- `key` и `version` — идентичность. Загруженная версия неизменяема: правка — это новый файл с тем же `key` и `version` на 1 больше. Прошедшие занятия ссылаются на старую версию.
- `card` — что видит обучаемый ДДС; для 112 карточка пустая, а ситуация описана в `intake112`.
- `events` — таймлайн: доклады в журнал связи, входящие звонки (`delivery: phone_incoming`), новые карточки. Якорь `since` — выдача карточки, статус или завершение звонка контакту; `expects` — какой статус и в какой срок ожидается в ответ.
- `reference` — эталон. Он виден только преподавателю и используется при оценке.

### Эталон оператора 112 (`intake112.reference`)

| Поле | Что задаёт |
|---|---|
| `expected_card.applicant_name` | ФИО заявителя; оценивается, только если заявитель назвал его в разговоре |
| `expected_card.address.*` | поля адреса: страна, субъект, округ, район, населённый пункт, улица, дом, корпус, строение, квартира, подъезд, этаж. Каждое необязательно и оценивается отдельно |
| `expected_types`, `expected_profiles` | ожидаемые типы и ответы в профильных картах по id полей каталога; `{"state": "unknown"}` — верный ответ «Неизвестно» |
| `expected_services` | ожидаемый список оповещённых служб |
| `alternatives` | допустимые варианты написания поля сверх обычной нормализации (регистр, «ё», пунктуация, порядок слов, сокращения) |
| `description_questions` | контрольные вопросы ИИ-судье к полю «Описание со слов заявителя» |
| `scoring` | поправки к рубрике: отключённые и критические критерии, веса |

Импорт проверяет согласованность: значение эталона, продублированное в фактах заявителя, должно совпадать после нормализации; поле карты, скрытое условиями видимости, не может быть в эталоне.

Факты заявителя (`intake112.dialogue.facts`) задают, что он знает, что сообщает сразу, а что — только в ответ на вопрос, по каким шаблонам вопросов факт раскрывается и какими словами отвечать. Персонаж и вступительная фраза — `intake112.dialogue.caller`. Такие сценарии удобнее создавать в веб-редакторе преподавателя.

## 4. Загрузка

Порядок важен: сценарии ссылаются на службы и коды классификатора.

```bash
emsim import services       --actor <логин администратора> seed/services.json
emsim import classifier     --actor <логин администратора> seed/classifier.json
emsim import intake-catalog --actor <логин администратора> seed/intake-catalog.json
emsim import scenarios      --actor <логин администратора> seed/scenarios
```

или одной командой:

```bash
emsim import seed --actor <логин администратора> seed
```

В compose то же делает `make seed`. `--actor` — логин активного администратора.

Повторная загрузка идемпотентна: неизменённые записи пропускаются. Попытка загрузить другое содержимое под уже существующими кодом службы или версией сценария отклоняется с ошибкой конфликта, ничего не записывается.

**Обновление старой установки.** Если у существующих пользователей указаны службы, которых нет в загружаемом справочнике, `import services` перечислит их коды и завершится ошибкой `orphan_service_codes`. Добавьте недостающие службы или поправьте профили пользователей и повторите импорт.
