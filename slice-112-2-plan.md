# Срез 112-2 — уточняющий опрос заявителя

Источник: `slice-planning-112.md` §5. Работы выполняются после отдельного
коммита с завершением 112-1; утверждённые версии сценариев и evidence не
переписываются.

## Результат

Оператор задаёт подготовленные вопросы в произвольном допустимом порядке,
получает только произнесённые ответы, сам заполняет карточку и может
поставить разговор на удержание. Преподаватель видит диалог, выясненные и
невыясненные факты и сохранённые изменения карточки.

## Семантика

- У нового сценария `intake112.dialogue` вместо `call.script`: начальная
  реплика, неизменяемые факты, вопросы с темой и подготовленным ответом.
  `available_after` содержит ID ранее заданных вопросов; циклы запрещены.
  `reveals` связывает произнесённые ответы с фактами. Старый `call.script`
  остаётся читаемым только у уже созданных версий 112-1.
- После `answer_incoming` новая версия произносит только начальную реплику.
  `ask_intake_question` принимает ID доступного вопроса и атомарно сохраняет
  вопрос оператора, ответ заявителя и состояние. Новый осознанный повтор
  вопроса возвращает тот же ответ; повтор `command_id` возвращает прежнюю
  квитанцию без новых реплик. Уточнение — отдельный вопрос с предусловием.
- `hold_incoming` и `resume_incoming` меняют состояние телефона; во время
  удержания новая реплика недоступна. `end_incoming` допускается также из
  удержания. Отправка карточки не завершает разговор.
- Клиент получает только текущие варианты вопросов и уже произнесённые
  реплики. Факты и будущие ответы остаются в неизменяемой версии сценария;
  после `stop` и окончания вызова новые реплики запрещены.
- ID вызова в этом срезе равен ID карточки: одно обращение на карточку.
  Реплика связывается с `command_id`, что позволяет совместить её с журналом
  сохранений карточки. Заполнение по ответам остаётся ручным.

## Коммиты

1. C1 — договор сценария, API/evidence, порт симулятора и валидация контента.
2. C2 — миграция типов действий, чистые правила и состояние диалога.
3. C3 — транзакционное исполнение, безопасная выдача и evidence.
4. C4 — версия 2 пилота и задания с адресом, числом пострадавших и неизвестным.
5. C5 — рабочее место, разбор и генерируемые типы клиента.
6. C6 — сквозные проверки и документация.

Рубрика остаётся ручной и не меняется. Свободный текст, профильные карты,
несколько служб и автоматическая оценка относятся к следующим срезам.
