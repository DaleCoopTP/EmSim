# План среза 112-6 — детерминированная оценка 112 (этап 1)

Дата: 2026-09-25. Решение пользователя: срез начинается до завершения этапа 2
среза 112-5b (замер W0 — отдельная последующая задача). Рубрика этого этапа —
полностью детерминированная (`operator112/rubric-v2`); LLM-критерии (полнота
описания, содержательность свободного разговора) — `operator112/rubric-v3`,
после этапа 2 112-5b.

Полное обоснование решений — [ADR-026](design-docs/adr/026-operator112-assessment-rubric-v2.md).
Этот файл — рабочий план: что именно меняется и в каком порядке.

## 1. Пользовательский результат

Обучаемый получает автоматическую оценку 112-карточки сразу после
«оповестить и сохранить» (или после stop, по последнему черновику):
100 баллов по шести блокам и четырём штрафам, основания видны
преподавателю в разборе. Оценка сравнивается с эталоном конкретного
сценария (`intake112.reference`), а не с текстом разговора напрямую.

## 2. Рубрика (сводка, детали — ADR-026)

| id | вес/штраф | эталон |
|---|---|---|
| `ADDRESS_FIELDS` | 35 | `expected_card.address.*`, кроме `object`/`landmark` |
| `PROFILE_CARDS` | 25 | `expected_types` + `expected_profiles` |
| `CALLER_TOPICS` | 15 | не нужен — словарь тем в `params` |
| `T_ANSWER` | 7.5 | не нужен — норматив 15 с в `params` |
| `T_FILL` | 7.5 | не нужен — норматив 90 с в `params`, минус ожидание ИИ-заявителя |
| `DESCRIPTION_PRESENT` | 10 | не нужен — `complaint` известен и непуст |
| `P_ADDRESS_REGION` | −10 | `expected_card.address.country`/`region`/`okrug` |
| `P_APPLICANT_NAME` | −5 | `expected_card.applicant_name`, только если факт раскрыт |
| `P_SERVICES` | −5×N | `expected_services` |
| `P_EXTRA_PROFILE` | −5×N | `expected_types`/`expected_profiles` |

Точные баллы полей адреса и словарь тем — `design-docs/contracts/rubric.operator112.json`'s `params`, не в коде.

### Правило «эталон отсутствует» → 0

Отсутствие эталона у блока/штрафа — **обычный ноль по той же бизнес-логике**,
не отдельный статус. `not_applicable` остаётся только за объективной
неприменимостью (нет разговора для `CALLER_TOPICS`, `interruptions`/stop до
этапа для тайминга). См. ADR-026 §"Правило «эталон отсутствует»" — таблица
там нормативна, здесь не дублируется.

Сиды `seed/scenarios/pilot-112-*.json` **не меняются** в этом срезе:
эталон в них остаётся тем, что уже есть (где есть `expected_types`/
`expected_services` — используется; `ADDRESS_FIELDS`/`P_APPLICANT_NAME`
дадут 0 до отдельного наполнения `expected_card`). Наполнение конкретных
сидов эталоном — отдельная, более поздняя работа (новая версия файла
сценария), не часть этого среза.

### Что проверяется

`notification.card_snapshot`, если оповещение состоялось; иначе
`final_card`. Legacy-маршрут (`intake_state.finale == ""`) — задача
`failed/operator112_legacy_route`, ручная оценка доступна как обычно.

## 3. Коммиты

Коммит-по-коммиту план (c1–c10) утверждён в Plan Mode и выполняется по

10. **c10** — документация (`README.md`, `seed/README.md`, `slice-planning-112.md`,

## 4. Definition of Done

- Эталонные прохождения: верное, с ошибочным адресом, с пропущенной темой,
  с неверным набором служб — воспроизводимый одинаковый результат на одном
  evidence.
- Пустой эталон (как в текущих сидах) даёт 0 по `ADDRESS_FIELDS`/
  `PROFILE_CARDS`, штрафы не начисляются, остальные блоки считаются как
  обычно — никакого `needs_review` только из-за отсутствия эталона.
- Ручная (экспертная) оценка доступна всегда, включая legacy-маршрут и
  занятия на `operator112/rubric-v1`.
- Обучаемый не видит эталонные значения нигде в своей проекции.
- `make verify`, `make verify-web`, `python3 design-docs/contracts/check.py`,
  `make test-integration`, `cd web && npm run test:e2e` — зелёные.

## 5. Вне объёма этого этапа

- LLM-критерии (`operator112/rubric-v3`) — после этапа 2 112-5b.
- Наполнение сидов реальным эталоном.
- Возможность связи с ДДС в оценке (112-10).
